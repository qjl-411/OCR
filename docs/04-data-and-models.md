# 数据 模型与真实训练

| 数据 | 使用范围 |
| --- | --- |
| 用户 23 张原始 PDF | 前 18 张产生监督训练裁剪，后 5 张开发验证；文字层回归另行报告 |
| 11 张 PDF 与 1 张 PNG 合成示例 | 清楚标识教学用途，验证业务、重复和金额异常 |
| 700 个合成字符串裁剪 | 训练数字、重复字符、金额和日期，不能冒充真实发票 |
| VATID 官方训练 0001–0020 | 20 张纸票的人工标注水平关键词，用于 CRNN 适配 |
| VATID 官方训练 0021–0025 | 5 张纸票的组件开发验证 |
| VATID 0051–0060 | 历史错误分析与输入预处理开发，不是最终独立集 |
| VATID 0061–0080 | 历史候选版本评估，不作为最终版本成绩 |
| VATID 官方测试 0081–0100 | 历史图片留出评估，存在同一发票不同照片跨划分，不是票据级独立集 |
| VATID 原训练划分 0030、0035 | 本项目从未使用的留出照片；同一张未见发票，60 个关键词 |
| 阿里云两份官方文档示例 | 两张不同发票、12 个预先人工抄录字段，外部独立小样本 |

原始 PDF、私人参考值、裁剪图和运行数据库不进入公开 Git 仓库。按人工查看原图印刷票号完成 100 张图片的身份分组后，排除 0001–0025 和 0051–0100 中全部发票身份，最终仅 0030、0035 留下。它们和外部两张示例均不参与项目训练或参数选择；历史图片级结果不据此改写为独立成绩。上游预训练数据未完整公开，无法排除上游重叠。VATID 原图通过下载脚本从固定提交取得，不在公开项目中再次分发。

## 真实训练

| 阶段 | 训练与开发样本 | 步数 | 实测 CPU 耗时 | 开发子集结果 |
| --- | --- | --- | --- | --- |
| PDF 与合成文本 | 1571 / 350 | 400 | 80.15 秒 | 60 条完全匹配 36 → 58；CER 7.48% → 0.43% |
| 真实纸票适配与原数据混合 | 2071 / 475 | 800 | 154.59 秒 | 120 条完全匹配 94 → 116；CER 4.16% → 0.62% |

CPU、PyTorch 2.8.0+cpu、4 线程、batch=8、Adam lr=0.00015，冻结 CNN，只更新两层双向 LSTM 与投影；固定 seed=20261120。逐步 loss、输入清单哈希、起止时间和检查点哈希在 `training/runs/*/run.json` 与 `metrics.jsonl`。开发子集不是全量开发集、更不是独立整票准确率。

## 数据解释

VATID 仅标注部分关键词，不能计算完整发票字段准确率、全票检测精确率或 F1。两张最终照片来自同一发票，统计单位和局限均明确保留；外部示例另报六项字段匹配，不与关键词指标混算。输入哈希、模型哈希、实现哈希、逐图结果和协议在对应报告。PDF 栅格衍生图只是同源回归，不能增加独立样本数量。附件中票面税额为星号时，仍保留未知，不擅自按金额差填写零税额。

## 独立数据取得与来源

新增两张外部图片分别采用官方 API 文档提供的示例链接，只下载原图，未调用这些厂商的识别服务。GT 来自首次推理前对原图人工目视抄录，字段为代码、号码、日期、不含税金额、税额和价税合计。选择依据是文档给出的固定示例，不按模型效果挑选。原图哈希和精确页面 URL 见 `data/external-evaluation-split.json`；不将文档示例假定为已核实的真实交易，原图不随公开源码再次分发。
