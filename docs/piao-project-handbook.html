票序 智能财务发票系统 v2.0

指定算法验收候选版：React + TypeScript 前端、FastAPI 后端、本地 SQLite。图片和扫描 PDF 实际使用 CTPN → CRNN → CTC，有文字层的电子 PDF 可直接解析。保留上传、批处理、复核、重复校验、费用分类、统计、审计和 Excel / CSV / JSON 导出。

本地算法与业务验证已经执行；Windows、macOS、Docker 和真实浏览器的最终验证尚待运行，当前不称为全部验收完成。 具体数据见 验收报告。PP-OCR 仅保留为需要明确选择的旧版对比通道，指定网络失败时直接报错，不回退。

运行

安装 64 位 Python 3.12，进入解压后的项目目录：

python start.py

Windows 可双击 start.bat，macOS / Linux 可运行 sh start.sh。首次安装依赖需联网；模型和依赖齐全后在本机处理发票，不调用云端 OCR。运行预构建界面不需要 Node.js。默认打开 http://127.0.0.1:8000，按 Ctrl+C 停止。

python start.py --port 8010 --no-browser
python start.py --no-demo
python start.py --install-only

建议 4 核 CPU、8 GB 内存、2 GB 可用磁盘；GPU 不是运行和本次微调的必要条件。macOS 运行库要求 13 或以上。数据保存在 runtime，也可用 INVOICE_DATA_DIR 指定位置。Git 源码中的模型分卷由启动器自动校验并重组；离线交付包直接附完整 ONNX 文件。

使用闭环

  1. 在识别中心上传 PDF / PNG / JPG / ZIP，保持指定算法选择。
  2. 算法验收时勾选“PDF 也强制走图像识别”，确保没有使用 PDF 文字层。
  3. 在待复核对照原图、识别框和提取字段，修订错误，确认或填写原因驳回。
  4. 必填字段、金额关系和重复检查通过后才能确认；统计仅计入已确认的非重复票据。
  5. 在台账筛选日期、分类、状态和来源，导出 Excel、CSV 或 JSON；操作记录保存变更历史。

票号和税号保留为字符串，金额使用 Decimal，未知税额保持 null。规则检查不提供税务真伪查验。模型分数不是准确率，所有新上传记录都进入人工复核。

数据与模型

私人交付包包含原始 23 张 PDF；公开 Git 源码排除原始发票、私人参考值、裁剪图和本地数据库。11 张初始 PDF 与额外 1 张 PNG 都明确标注为虚构教学示例。

CTPN 使用原始 VGG16 / 双向 LSTM 预训练网络并进行数值校验；CRNN 使用 7 个卷积层和两层双向 LSTM，实际微调两阶段共 1200 步；训练为 CTCLoss，推理显式 CTC 解码。权重、来源、SHA-256 和逐步 loss 均随包提供，详见 数据与模型 和 训练复现。

独立评估严格按票据身份排除训练和历史开发数据：VATID 0030、0035 是同一张未见发票的两张照片；另有两份此前未用的官方文档发票示例。样本非常小。0081–0100 存在票据身份重合，只保留为图片留出成绩。水平关键词端到端召回为 29/50；外部示例的六项字段合计命中 5/12，不能称为高精度整票识别。竖排标签未有效支持，所有新发票需要人工复核。

票序界面设计规范

视觉方向

采用克制的财务工作台风格：浅灰画布、白色卡片、深松绿导航和主操作，辅以薄荷绿、琥珀色与蓝色区分状态。中文使用系统无衬线字体；金额使用等宽数字。图标采用统一线条图标，避免大量装饰性图片影响票据可读性。

桌面左侧 224px 常驻导航，顶部为位置、搜索入口和单机工作区标识。内容区域包含页标题、操作、关键数据卡与主要工作区。窄屏导航收起到抽屉，表格保持横向滚动；复核页面改为上下布局。

设计细节

主色 #164c3d，画布 #f4f6f8，正文 #182b26，次级文字 #6b7873，边框 #e4e9e6。主字号 16px，常用说明 14px，辅助信息不小于 12px。圆角 12–18px，卡片阴影轻微，主区域留白 24–32px。

所有操作有明确的等待、成功、失败反馈；按钮在请求中禁用；弹窗支持 Escape、焦点约束与关闭；文件状态与异常同时使用文字和颜色表达。金额、票号与状态列位置稳定，票据复核时始终保留原始识别文本与人工修改记录。

架构与开发说明

浏览器加载 React 预构建页面，通过同源 API 调用 FastAPI；后台单进程队列处理上传，SQLite 保存业务与审计，文件系统保存原件和预览。

处理流程： 批量上传 → 格式检查 → 本地队列 → PDF 直接读取或图片 OCR → 字段提取与校验 → 人工修订、确认或驳回 → 统计与导出。

指定网络

CTPN 为原始 VGG16 的 13 个卷积加 RPN 卷积，stride=16 特征图的每一行输入隐藏维 128 的双向 LSTM，再经 512 维线性投影、十组锚框分类和回归。后处理执行概率筛选、NMS、相邻锚框图连接，生成文本行。

转换按原冻结图映射参数，将 TensorFlow i,j,f,o 门顺序改为 PyTorch i,f,g,o，并加入原图 forget_bias=1；线性投影之后不能擅加 ReLU。以 OpenVINO 读取并执行的原冻结图作为数值参考，不声称运行过独立 TensorFlow 环境。三尺寸实际误差保留在转换报告。

CRNN 为七层卷积、两层隐藏维 256 的双向 LSTM 与字符投影，输入固定高度 32、动态宽度，输出 time × batch × 6736。字符表 6735 个字符，标签 0 为 blank。训练使用 CTCLoss；推理先合并相邻重复标签，再移除 blank，例如 A,A,blank,A 得到 AA。

暗照片曝光归一化、长表格横线处理、邻行碎片清理和空列间距压缩属于输入处理。标签明确但号码格式不完整、或金额小数点缺失时，可在同一 CRNN 上以不同宽度重读，只采用实际输出候选，不补写数字或从其他字段反推税额。

运行时使用 CPU ONNX Runtime 1.23.2，启动前校验模型 SHA-256；关闭遥测。模型或依赖不齐直接报错，指定网络模块不导入、不调用 PP-OCR。图像记录 engine=ctpn_crnn_ctc，PDF 直接提取为 pdf_text，旧版比较为 ppocr，分别保留。

业务一致性

上传配置和模型版本参与文件去重；同一原件可分别验证文字层与图像通道。不同文件中相同票号仍标记业务重复并阻止确认。金额使用 Decimal，未知值保存 null。修改携带 revision，旧版本冲突被拒绝；保存后退回复核，统计仅含人工确认且不重复的票据。

文件级处理完成后再写入，避免后页失败留下半份记录。中断任务重启后标记失败，已成功文件可重新导入并跳过。限制大小、页数、像素与 ZIP 路径，Excel/CSV 导出处理公式风险和长数字类型。

主要代码

reader.py 路由格式和识别模式；classic_ocr 是指定网络；parser.py 提取和验证；service.py 队列、去重与统计；exporter.py 导出；main.py API；frontend/src 为七个页面和复核交互。训练和数值转换与日常运行依赖分开。

数据解释

VATID 仅标注部分关键词，不能计算完整发票字段准确率、全票检测精确率或 F1。两张最终照片来自同一发票，统计单位和局限均明确保留；外部示例另报六项字段匹配，不与关键词指标混算。输入哈希、模型哈希、实现哈希、逐图结果和协议在对应报告。PDF 栅格衍生图只是同源回归，不能增加独立样本数量。附件中票面税额为星号时，仍保留未知，不擅自按金额差填写零税额。

独立数据取得与来源

新增两张外部图片分别采用官方 API 文档提供的示例链接，只下载原图，未调用这些厂商的识别服务。GT 来自首次推理前对原图人工目视抄录，字段为代码、号码、日期、不含税金额、税额和价税合计。选择依据是文档给出的固定示例，不按模型效果挑选。原图哈希和精确页面 URL 见 data/external-evaluation-split.json；不将文档示例假定为已核实的真实交易，原图不随公开源码再次分发。

查询参数

/api/invoices 支持 q、status、category、source、start、end、sort、page 和 page_size。日期为 YYYY-MM-DD；每页默认 10 条，最大 100 条。排序包括 newest、date_desc、amount_desc。状态可用 needs_review、approved、rejected，以及异常集合 anomaly 和重复集合 duplicate。来源为 provided、upload、demo；空值表示不限。

/api/dashboard 支持 start、end、source。金额统计只包含已确认且非重复的票据。

/api/export 支持相同的查询条件、ids（逗号分隔）和 format（xlsx / csv / json）。ids 与筛选条件取交集，空结果返回 422。

上传与轮询

curl -F "pipeline=classic" -F "force_ocr=true" -F "files=@example.pdf" http://127.0.0.1:8000/api/imports
curl http://127.0.0.1:8000/api/jobs/返回的任务id

上传接口接受 multipart 表单，字段名重复使用 files，返回 HTTP 202 和任务对象。接受上传不代表识别完成；应轮询任务的 status。文件级识别错误保存在 results，导入前的格式或 ZIP 条目问题保存在 errors。total 与 processed 按文件统计，PDF 的每页可能生成单独票据。

人工修改与确认

修改接口要求提交全部可编辑字段和当前 revision。保存成功后返回更新后的票据与新版本。确认请求示例：

{"revision": 2, "verdict": "approved", "note": ""}

verdict 可为 approved、rejected 或 needs_review。驳回需要非空原因。存在必填缺失、金额不平或重复时，确认返回 422。版本冲突返回 409，调用者应重新读取，不能静默覆盖。

常见返回状态

状态码 含义
200 查询或操作成功
202 上传已接受，任务进入队列
403 跨站写入被拒绝
404 记录、文件或接口不存在
409 数据版本过期
413 批次或上传数量超出限制
422 参数、空导出、复核条件等检查失败
503 缺少前端构建文件

指定识别模式

上传表单另接受 pipeline=classic|ppocr 和 force_ocr=true|false，默认 classic、false。数据集导入接受相同查询参数。engine 分别为 pdf_text、ctpn_crnn_ctc、ppocr。processing_profile 保留配置、模型版本、原件哈希和耗时。指定网络失败直接报错，不回退其他模型。

算法说明

Qt 改为前后端获得了用户授权；算法仍实际使用 CTPN、CRNN 与 CTC。CTPN 是有来源的原始预训练检测网络，CRNN 是经典七层卷积和两层双向 LSTM 并真实微调，CTC 的训练和推理解码都可检查。不能说从零训练了 CTPN，也不能把 PP-OCR 模型或其成绩作为指定网络成果。

如何解释结果

分别解释 PDF 文字层、固定衍生回归、开发裁剪和独立小样本。去重后的同一发票两张照片，水平关键词 GT 裁剪为 50/50，但端到端只命中 29/50，竖排 0/10；它们不能证明广泛的整票准确率。两张外部示例六项字段合计 5/12，原始错误必须展示。历史 20 张图片的 95.8% 裁剪成绩存在票据身份重合，只能列为图片留出测试，不能再称独立成绩。模型置信分数也不是准确率。

为什么人工复核仍然必要

遮挡、反光、纸张、字体、边框、密集数字和版式会导致误识别。格式和金额规则只能检查一致性，不能保证每个字符正确。所有新上传票据都需对照原件确认；项目不提供税务真伪或抵扣资格判断。

训练与复现操作

本项目已经在 CPU 上完成两阶段 1200 步训练，无需你准备 GPU。当前机器实测分别约 80.2 秒与 154.6 秒；其他机器请先跑 100 步测速度再估算。建议 Python 3.12、4 核 CPU、8 GB RAM、5 GB 可用磁盘用于训练环境。下面命令以 Linux 为已验证环境；Windows 的解释器路径换为 .venv\Scripts\python.exe。
